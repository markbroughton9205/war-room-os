# War Room Runtime Roadmap

## Phase A: Stable Web/PWA Shell

The current priority is a stable web and PWA shell. The app should load fast, mount only the active page, avoid hidden polling, keep chat usable, preserve memory when configured, and route all risky work through approval gates.

## Phase B: Desktop Native App Shell for Windows

The next runtime layer is a Windows desktop shell. This should make local agents, files, repo awareness, diagnostics, and controlled background workers feel native while preserving the same approval model. Local engines may be detected and invoked, but code edits, commits, deployments, rollbacks, and financial actions still require explicit approval.

## Phase C: Mobile Companion App

The mobile companion should focus on command, approvals, notifications, mission status, memory review, and secure handoff. SMS can notify and collect low-risk responses, but payment, banking, legal, identity, deployment, and external submission actions require secure War Room approval.

## Phase D: AI-First Operating Environment

The final direction is an AI-first operating environment where the Kernel routes work by capability, workers coordinate across income, code, memory, files, repo, deployment, and payments, and Ra'el remains the command authority. The system can recommend, prepare, organize, verify, and track work, but external execution requires the proper approval gate.
