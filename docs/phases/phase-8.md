# Phase 8: War Room Constitution and Operational Doctrine Foundation

## Purpose

Phase 8 establishes War Room as a governed operational intelligence platform. The goal is to turn the existing feature stack into a system with durable doctrine, explicit approval boundaries, memory refinement, engineering routing, and disciplined turn behavior.

This phase does not add theatrical identity or marketing language. It defines the operating rules that future features, agents, councils, and client surfaces must respect.

## Primary Outcomes

- Publish the War Room Constitution as the authoritative platform doctrine.
- Define command authority and approval gates for risky work.
- Establish model family roles and future family modularity.
- Clarify memory classes, retention expectations, and doctrine formation.
- Formalize engineering routing from issue detection through audit logging.
- Improve turn discipline so War Room stays concise, grounded, and useful.

## Governance Foundation

Phase 8 should introduce governance as a product capability. Governance is not only documentation; it is the structure that determines how future actions are proposed, reviewed, approved, logged, and remembered.

Required governance surfaces:

- Command authority rules.
- Approval categories and escalation triggers.
- Permission scopes for agents, tools, providers, and operators.
- Audit expectations for significant actions.
- Doctrine references available to orchestration and review systems.

## Turn Discipline

War Room responses should prioritize operational clarity. The system should identify the user's intent, retrieve relevant context, decide whether action is safe, and respond with useful next steps or a prepared proposal.

Turn behavior should avoid:

- Unbounded self-review loops.
- Repeated validation after a successful pass.
- Fake certainty when evidence is missing.
- Excess summaries that do not change decisions.
- Roleplay, lore, or theatrical behavior.

Turn behavior should prefer:

- Evidence-backed statements.
- Explicit uncertainty.
- Clear approval asks.
- Short progress updates for long-running work.
- Actionable options when trade-offs exist.

## Approval Systems

Phase 8 should define approval boundaries before expanding autonomy. War Room may prepare work without approval when the action is local, reversible, and within scope. It must request approval before production mutation, deployment, spending, external communication, permission expansion, credential changes, or destructive operations.

Approval records should capture:

- Proposed action.
- Requesting agent or subsystem.
- Risk category.
- Evidence summary.
- Commander decision.
- Execution result.
- Follow-up audit details.

## Memory Refinement

Phase 8 should distinguish live memory, archive memory, and strategic memory in product behavior and documentation. The system should promote durable lessons into strategic memory and discard low-value interaction noise.

Memory refinement priorities:

- Importance scoring for decisions, failures, patterns, and doctrine.
- Compression of completed work into durable summaries.
- Recall based on project, mission, risk, operator, and prior decisions.
- Retention rules that prevent meaningless chatter from polluting memory.
- Review paths for doctrine changes and strategic memory promotion.

## Engineering Routing

Engineering work should follow a governed path:

1. Issue detected.
2. Proposal generated.
3. Diff preview prepared.
4. Red Team review requested when risk justifies it.
5. Commander approval obtained.
6. Change applied.
7. Validation executed.
8. Audit log updated.

Cursor, Codex, Claude, Red Team, and future engineering agents should be routed by task fit. No engineering agent may silently change production, deploy, alter billing, or broaden permissions.

## Implementation Scope

Phase 8 should remain focused on doctrine and control foundations. Product and code work should be limited to features that make doctrine enforceable or visible.

In scope:

- Doctrine documents and roadmap alignment.
- Approval category definitions.
- Memory classification design.
- Engineering workflow policy.
- Audit model planning.
- Council routing guidelines.

Out of scope:

- Fully autonomous production execution.
- Broad SaaS account implementation.
- Long-lived background worker fleet.
- Agent marketplace or dynamic agent spawning.
- Provider benchmarking automation beyond initial design.

## Acceptance Criteria

- The War Room Constitution exists and is treated as platform doctrine.
- Phase 8 roadmap documents governance, turn discipline, approval systems, memory refinement, and engineering routing.
- Future phases can reference this doctrine without redefining authority boundaries.
- Documentation is clear enough to guide implementation, review, and escalation decisions.
